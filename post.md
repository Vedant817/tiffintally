## What I Built

Home tiffin cooks take orders on WhatsApp, usually late in the evening, in Hinglish:

"Kal lunch 2, dinner skip."
"Aaj raat 1 thali, bina pyaaz lahsun."
"Roommate left, cancel one thali from tomorrow."

Someone has to turn that chat into a count of plates, a list of special requests and a record of who owes what. A missed cancellation wastes groceries; a missed extra order loses a customer.

You paste a WhatsApp export. TiffinTally:

Parses the chat and extracts order events (meal, quantity, new or cancel, dietary notes, payments).
Applies cutoff times and re-statements ("kal lunch 2" followed by "kal lunch 3 kar do").
Builds a kitchen prep sheet and a dues ledger. A payment mentioned in chat stays a claim until the cook confirms it.
Masks phone numbers, addresses and names before any message goes to a hosted model.

## The honest-evals part

Most of my time went into finding out what I could not claim.

What is measured today. Only the offline regex rules, on the 50 rows of the frozen synthetic test set. Strict match (meal, quantity, action, mods, payment, secondary customer) is correct on 35 of those 50 rows; lenient match (meal, quantity, action) on 47 of 50. Accuracy percentages, Wilson intervals and the source file for every number are in `RESULTS.md`, generated by `scripts/publish_results.py` from saved per-row outputs.

What is not measured. The base model, a few-shot model, my fine-tuned adapter and a hosted Gemma run are all marked NOT RUN in `RESULTS.md`. I do not claim any model beats the rules.

Why I trust even those numbers only a little.

The data is synthetic; the labels come from the templates that generated the text.
The test split shares sibling templates with the training split. I documented this in `docs/KNOWN_LEAKS.md`, and the intervals do not correct for it.
I had earlier reported model accuracy figures. The per-row outputs were never saved and the adapter cannot be re-scored, so I retracted them. The old logs are kept under `evals/retracted/`.
An audit found five regex patterns I had fitted to test rows. I removed them, and the regex score went down.

A failure you can reproduce. The rules read "don't send lunch" as one new lunch order:

```python
from tiffintally.extract.base import heuristic_extract

heuristic_extract("don't send lunch", "Ravi")  # action=new, meal=lunch, qty=1
heuristic_extract("kal lunch mat bhejna", "Ravi")  # action=cancel, meal=lunch, qty=0
```

Both lines are what that command prints today, 17 October 2026. I have not measured how any model does on English negation, so I make no claim either way.

## How I Built It

Stack: FastAPI, Pydantic, uv, pytest. The suite has 328 passing tests and 4 expected failures, and CI is green.

Extraction backends, chosen by environment variables:

Offline regex rules (default, no network).
Gemma through Google AI Studio when `GOOGLE_API_KEY` is set, default id `gemma-4-26b-a4b-it`. No run of it has been measured, so I claim nothing about its accuracy.
A Qwen2.5-3B LoRA adapter on Modal. The Qwen base is a research licence, so it is non-commercial; I treat it as an experiment. The adapter is not published and not measured in this release. If it is ever distributed, its licence is separate from this repository's MIT licence, and "Built with Qwen" attribution is required.
Any OpenAI-compatible endpoint, such as local Ollama. It is wired in but I have not measured it.

Model output is untrusted. Messages are numbered in the batch and replies are matched by index. A message the model skips falls back to the rules and is flagged for review. Quantities are bounded and prompt-injection text is flagged.

Privacy. Nothing is written to disk by default. The opt-in SQLite mode (`TIFFINTALLY_PERSIST=1`) stores masked text: one pseudonymizer per upload replaces every sender name, every roommate named in a message, phone numbers, email addresses and flat or building numbers with sequential tokens, in the stored lines and in the customer, secondary customer and payment note columns. A street name with no flat number in front of it is not matched, so street names can remain. A test pastes an export and reads every table plus the database, WAL and shared-memory bytes, asserting that no name, phone number, email or building name reaches disk.

Reconciliation and the ledger are plain deterministic code, so counts and money never depend on a model.

Why open matters here

The rules path runs on a laptop with no internet, so a cook's customer list never has to leave the kitchen. An open-weight model behind a local endpoint extends that. If a hosted model is used, the masked text goes to that provider and spends the owner's quota. Gemma ships its own terms of use for commercial use; read them before charging a cook for this. I have not measured how much any of this saves.

What is next

A small set of real, human-written cook messages with hand labels. Until that exists, nothing here says how the app performs on real chats.
